# Speech2Text 0.2

Локальная транскрибация русскоязычных записей встреч (аудио и видео) с
разделением по спикерам. Вся обработка идёт на своей машине (macOS или Linux):
содержимое записи никуда не отправляется (подробнее в разделе «Приватность
и работа офлайн» ниже). На Apple Silicon вычисления автоматически ускоряются
через Metal (MPS); на Linux (и на Intel-Mac) скрипт считает на CPU, если не
поставить GPU-сборку PyTorch отдельно (см. «Установка»).

Стек:

- **[GigaAM-v3 (RNNT)](https://github.com/salute-developers/GigaAM)**: распознавание речи.
- **[pyannote.audio](https://github.com/pyannote/pyannote-audio)** (`speaker-diarization-3.1`): диаризация, кто и когда говорил.
- **ffmpeg**: приведение любого аудио/видео к 16 кГц моно.

Распознавание и диаризация запускаются параллельно в двух процессах, поэтому
общее время обработки равно длительности более медленного из двух шагов.

## Что делает скрипт

1. Ищет в папке с исходниками (`config.INPUT_DIR`) все поддерживаемые аудио- и
   видеофайлы:
   - **аудио**: `.wav .mp3 .m4a .aac .flac .ogg .opus .wma .aiff`
   - **видео** (звук извлекается автоматически, видеодорожка не нужна):
     `.mp4 .mov .mkv .avi .m4v .webm`

   Полный список: `SUPPORTED_EXTENSIONS` в `config.py`.
2. Конвертирует каждый файл через ffmpeg во временный WAV 16 кГц моно.
3. Параллельно запускает GigaAM (текст со словными таймкодами) и pyannote (интервалы спикеров).
4. Накладывает слова на интервалы спикеров, склеивает их в реплики и убирает короткие «вспышки» переключения спикера.
5. Записывает результат в папку `config.OUTPUT_DIR` в формате Markdown (`.md` по умолчанию) или обычного текста (`.txt`).
6. Прогоняет результат через словарь автозамены терминов (`terminology.txt`).
7. Переносит исходный медиафайл в подпапку `Архив` внутри папки с исходниками.
8. Пишет технический лог (`log_tech.txt`) и лог обработанных файлов (`log_user.txt`).

Если распознавание или диаризация уже посчитаны, но скрипт прервался
(например, при ошибке или ручной остановке), промежуточный результат
сохраняется в `.checkpoints/` и при повторном запуске не пересчитывается.

## Приватность и работа офлайн

**Содержимое записи (аудио/видео и распознанный текст) никуда не отправляется.**
ffmpeg, GigaAM и pyannote: весь расчёт идёт локально, в процессе на этой же
машине; ни один из них не грузит куда-либо аудио, видео или транскрипт.

При этом со скачиванием и проверкой самих *моделей* не всё так однозначно:

- **GigaAM** качает веса модели один раз (с CDN Сбера, не Hugging Face) в
  `~/.cache/gigaam`. После этого при загрузке модели он просто проверяет, что
  файл уже лежит на диске, и в сеть не обращается вообще: ни к CDN, ни куда-либо ещё.
- **pyannote** (модели диаризации) устроен иначе: он хранит кэш в
  `~/.cache/huggingface`, но **при каждом запуске** обращается к huggingface.co,
  чтобы проверить версию/доступ к gated-модели: отправляется служебный
  HTTP-запрос с твоим `HF_TOKEN`, без содержимого записи. Это подтверждено
  эмпирически (перехватом трафика), а не только по документации. Если
  интернета нет, запрос молча не проходит, и pyannote берёт модель из
  локального кэша; сама транскрибация не ломается, но попытка обращения к сети
  происходит каждый раз.

Если нужна гарантия, что скрипт вообще не будет пытаться связаться с сетью
после первоначальной настройки (например, для работы в изолированном
контуре), один раз убедитесь, что все модели уже скачаны (обычный запуск с
интернетом), а затем запускайте с переменной окружения:

```bash
HF_HUB_OFFLINE=1 python3 transcribe.py
```

Это отключает любые сетевые проверки в huggingface_hub: вместо запроса к
серверу сразу используется локальный кэш.

## Структура проекта

```
Speech2Text 0.2/
├── transcribe.py          # основной скрипт: транскрибация + постобработка + ручная очистка
├── config.py               # все настройки проекта (папки, модели, формат)
├── terminology.txt          # словарь автозамены терминов (редактируется вручную)
├── run_transcribe.command  # запуск в один клик (двойной клик в Finder, только macOS)
├── requirements.txt        # зависимости Python
├── .env                     # токен Hugging Face (не в git)
├── .env.example             # шаблон .env
├── Аудиозаписи/             # папка для исходников по умолчанию
├── Транскрипты/             # папка для готовых транскриптов по умолчанию
├── .checkpoints/            # промежуточные результаты незавершённых запусков
├── log_tech.txt             # технический лог выполнения
├── log_user.txt             # лог обработанных файлов (время начала/конца)
├── gigaam-env/               # виртуальное окружение Python (не в git)
└── Постановка/                # исходная инструкция и постановка задачи
```

## Настройки (`config.py`)

Все параметры вынесены из кода в отдельный файл `config.py`.

- **Папки по умолчанию**: `DEFAULT_INPUT_DIR` и `DEFAULT_OUTPUT_DIR` указывают
  на подпапки проекта `Аудиозаписи` и `Транскрипты`.
- **`OUTPUT_FORMAT`**: `"md"` (Markdown, по умолчанию) или `"txt"` (обычный текст).
- **Модели и параметры диаризации**: `ASR_MODEL`, `DIARIZATION_MODEL`,
  `NUM_SPEAKERS` (число спикеров, `None` = автоопределение),
  `MIN_FLICKER_DURATION` / `MIN_FLICKER_WORDS` (склейка коротких «вспышек»
  переключения спикера).
- **`SPEAKER_NAMES`**: сопоставление «Спикер 1» → реальное имя, если оно известно заранее.
- **`SUPPORTED_EXTENSIONS`**: какие аудио/видео форматы обрабатываются.
- **`TERMINOLOGY_FILE`**: путь к словарю автозамены терминов, `terminology.txt`
  в проекте по умолчанию.

Секреты (токен Hugging Face) хранятся отдельно, в `.env`, и в `config.py` не попадают.

### Личные пути (`config_local.py`)

Если нужно направить скрипт на папки вне проекта (например, на Яндекс.Диск),
**не редактируйте `config.py`.** Скопируйте `config_local.py.example` в
`config_local.py` и укажите свои пути в `OVERRIDE_INPUT_DIR`,
`OVERRIDE_OUTPUT_DIR` и/или `OVERRIDE_TERMINOLOGY_FILE`:

```bash
cp config_local.py.example config_local.py
```

`config_local.py` в `.gitignore`: он не попадает в git, так что абсолютные
пути конкретного компьютера не светятся в репозитории. Если файла нет или в
нём не задана какая-то из переменных, используются базовые папки проекта.

## Установка

Понадобится Python 3.11, ffmpeg и аккаунт на [huggingface.co](https://huggingface.co).
Python 3.12+ не подходит: часть зависимостей GigaAM и pyannote может не собраться.

### 1. Системные зависимости (Python 3.11 и ffmpeg)

**macOS** (через [Homebrew](https://brew.sh)):
```bash
brew install ffmpeg python@3.11
```

**Linux (Debian/Ubuntu)**:
```bash
sudo apt update
sudo apt install ffmpeg python3.11 python3.11-venv
```

**Linux (Fedora/RHEL)**:
```bash
sudo dnf install ffmpeg python3.11
```
(если ffmpeg недоступен из стандартных репозиториев, подключите RPM Fusion
или поставьте статическую сборку с [ffmpeg.org](https://ffmpeg.org/download.html))

### 2. Виртуальное окружение и зависимости

```bash
python3.11 -m venv gigaam-env
source gigaam-env/bin/activate
pip install -r requirements.txt
```

На Linux с NVIDIA-видеокартой `requirements.txt` поставит обычную (CPU) сборку
PyTorch, расчёт пойдёт на процессоре. Чтобы использовать GPU, поставьте
CUDA-сборку PyTorch **до** `pip install -r requirements.txt`, по инструкции
[pytorch.org/get-started/locally](https://pytorch.org/get-started/locally/)
(выбрать Stable → Linux → Pip → CUDA), а затем доустановить остальные
зависимости из `requirements.txt`. На Apple Silicon отдельно ничего ставить не
нужно: ускорение через MPS работает из коробки.

### 3. Доступ к моделям pyannote

Принять условия доступа к gated-моделям под своим аккаунтом Hugging Face:
[pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1) и
[pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0).

### 4. Токен Hugging Face

Скопировать `.env.example` в `.env` и вписать свой read-токен:
```
HF_TOKEN=hf_ваш_токен
```

Подробная пошаговая инструкция для macOS (Homebrew, Automator-ярлык и т.п.)
есть в файле [Постановка/Транскрибация GigaAM.md](Постановка/Транскрибация%20GigaAM.md);
для Linux она не актуальна в части системных шагов, но описание самого
скрипта и словаря замены терминов справедливо для обеих систем.

## Запуск

Положить аудио или видео встречи в папку `Аудиозаписи` (или в папку, указанную
в `config.INPUT_DIR`), затем:

```bash
source gigaam-env/bin/activate
python3 transcribe.py
```

На macOS можно также запустить двойным кликом по `run_transcribe.command`
(в Finder); на Linux это не сработает, используйте команды выше или свой
shell-скрипт/systemd-юнит. Можно также обработать конкретный файл, указав
путь к нему аргументом:

```bash
python3 transcribe.py /путь/к/файлу.mp4
```

Результат появится в папке `Транскрипты` (или в переопределённой
`config.OUTPUT_DIR`), исходник переместится в `Архив`.

## Словарь автозамены (`terminology.txt`)

Обычный текстовый файл, который правится вручную: код трогать не нужно, он
перечитывается при каждом запуске. Применяется автоматически после каждой
транскрибации, но можно прогнать и вручную, отдельным файлом:

```bash
python3 transcribe.py --clean входной.md [выходной.md]
```

Формат: одна запись на строку.

- `шаблон -> замена | описание`: автозамена. Например, `Едо -> ЭДО | ЭДО (вариант «Едо»)`.
- `!шаблон | причина`: только подсветить в отчёте (счётчик «Проверки»), текст не меняется. Используется, когда решает контекст.

«Шаблон» по умолчанию: обычное слово или фраза, регистр не важен, границы
слова подставляются автоматически. Если нужен настоящий регулярный шаблон
(символьные классы, `\s+`, повторения), поставьте перед ним `~`, тогда он
используется как есть. Строки с `#` считаются комментариями.

## Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| `ОШИБКА: не найден HF_TOKEN` | нет `.env` рядом со скриптом или в нём опечатка: должна быть строка `HF_TOKEN=hf_...` |
| Ошибка доступа к gated-модели | не приняты условия на страницах моделей pyannote под тем же аккаунтом, чей токен в `.env` |
| `ffmpeg: command not found` | ffmpeg не установлен или не виден в PATH. На macOS скрипт сам добавляет пути Homebrew, но сам ffmpeg должен быть установлен (`brew install ffmpeg`); на Linux используйте `apt install ffmpeg` / `dnf install ffmpeg` |
| Все реплики свалились в одного спикера | запись велась на один микрофон в переговорке; частично помогает задать `NUM_SPEAKERS` в `config.py` |
| Текст рвётся на мелкие куски | увеличить `MIN_FLICKER_DURATION` в `config.py` |
| Не найдено медиафайлов | файл лежит не в `INPUT_DIR` или расширение не входит в `SUPPORTED_EXTENSIONS` |
